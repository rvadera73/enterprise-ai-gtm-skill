## Example: Linear (DevTools SaaS)

### Framework Selection
- **Product type**: DevTools/Infrastructure
- **Stage**: Growth (product-market fit established)
- **Framework to use**: April Dunford Canvas

### Phase 1: Discovery
**Artifacts produced**:
1. Job definition: "Reduce issue triage time from 5+ hours to 30 minutes"
2. Customer persona: "Tech Lead at 10-200 person SaaS startup"
3. Pain quantification: "Wasting $75K/year per team on slow issue management"
4. Alternative landscape: Jira (bloated), GitHub Issues (limited), Asana (overkill)
5. Aha moment: "When team spends 2 hours triaging one day, realizes tool is broken"
6. Value Prop Canvas: Completed, visual

### Phase 2: Positioning
**Artifact produced**:
```
FOR Tech Leads at 10-200 person SaaS startups,
WHO waste 5+ hours/week on slow, bloated issue tracking,
Linear is the ONLY issue tracker that prioritizes developer speed and experience
THAT reduces triage time from 5+ hours to 30 minutes.

UNLIKE Jira (bloated, expensive):
- We're fast; they're slow
- We're $80/month; they're $500/month
- Built by engineers; built by enterprise managers

BECAUSE:
- Founded by engineers from Stripe, Google, Facebook
- Chosen by 5,000+ engineering teams
- 3x faster than Jira on standard workflows
```

### Phase 3: Validation
**Artifacts produced**:
1. Perceptual map (positioned vs. Jira/GitHub/Asana)
2. 5-second clarity test results (82% understood in <5 sec)
3. Messaging clarity score (94/100)
4. Competitive messaging matrix

### Phase 4: Messaging & Brand
**Artifacts produced**:
1. Segment-specific positioning (Tech Lead, Engineer, Enterprise Manager)
2. Brand archetype: The Creator + The Hero
3. Brand voice guide: "We move fast. Our tool should too."
4. Messaging by channel (LinkedIn, docs, Twitter, email)
5. Sales collateral (vs. Jira one-pager, vs. GitHub one-pager)
6. Website messaging (homepage, pricing, feature pages)
7. Email campaign framework
8. Social content themes (30-day calendar)

### All Framework Artifacts (23 Total)
✅ Complete, strategic, decision-backed
✅ Every artifact serves the positioning
✅ Consistent messaging across channels
✅ Ready for downstream marketing automation

## Implementation Path

### For Ask-AI (Example)

**Your product**: Conversational knowledge platform  
**Product type**: B2B Application SaaS (knowledge workers)  
**Stage**: Growth/Production-ready  
**Framework to use**: Geoffrey Moore Template OR April Dunford Canvas

**4-6 Week Timeline**:

**Week 1-2: Discovery**
- Interview 10 enterprise knowledge workers on "knowledge search job"
- Map Value Proposition Canvas
- Identify alternatives (Google Enterprise, Slack, SharePoint, do-nothing)
- Quantify pain (2-4 hours/day wasted searching)

**Week 3: Positioning**
- Fill Geoffrey Moore template
- Define "conversational knowledge" as the category you own
- Identify primary target (Enterprise knowledge workers at 500+ person companies)
- Differentiate vs. Google Enterprise (conversational vs. keyword), Slack (enterprise-wide vs. Slack-only)

**Week 4: Validation**
- Perceptual map (where do customers perceive the need?)
- 5-second clarity test with 20 target customers
- Message testing (do they understand your value in one sentence?)

**Week 5-6: Messaging & Artifacts**
- Segment by role (HR, Sales, Operations, Finance, Knowledge Manager)
- Create 5-6 segment-specific positioning statements
- Brand archetype: The Sage (clarity) + The Mentor (guidance)
- Produce 23 artifacts (job definition, personas, one-pagers, etc.)

**Then**: Feed Positioning Brief to marketing automation, generate 30+ marketing assets

## Critical Success Factors

1. **Framework Selection is Make-or-Break**
   - Wrong framework = wrong positioning = wasted marketing
   - Right framework = strategic clarity = high-converting messaging
   - Framework choice depends on product type, not on gut feeling

2. **Artifacts Serve the Framework**
   - Don't create artifacts ad-hoc
   - Framework determines which artifacts to produce
   - Framework outputs guide marketing automation

3. **Automation Scales What Framework Validates**
   - Framework proves positioning is right
   - Automation then generates dozens of assets at that positioning
   - Without framework, automation is just generating noise

4. **Iteration is Framework-Based**
   - Monthly review: is the positioning still valid?
   - Customer feedback feeds back into framework
   - Pivot: use framework to test new positioning before full rebrand
