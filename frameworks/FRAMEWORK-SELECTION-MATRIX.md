# Framework Selection Matrix

**The Decision Engine**: Which positioning framework to use based on product type + stage

This single matrix makes the skill reusable for ANY enterprise product.

---

## How To Use This Matrix

### Step 1: Identify Your Product Type
- DevTools/Infrastructure
- B2B Application SaaS
- Platform/Marketplace
- Enterprise AI Service
- Government SaaS

### Step 2: Identify Your Stage
- Pre-launch (MVP, validating problem)
- Growth (product-market fit, scaling)
- Mature (market leader, defending position)

### Step 3: Look up recommended framework
- Primary framework
- Secondary framework
- Why this combination

### Step 4: Tailor by buyer type (in messaging)
- Messaging changes, framework stays the same

## The Matrix

### 1. DevTools / Infrastructure SaaS

**Examples**: Stripe, Vercel, Linear, Supabase, Retool

#### Pre-Launch
- **Primary**: Lean Canvas + JTBD
- **Why**: Validate the problem exists, prove the job needs doing
- **Goal**: Problem validation, founder credibility
- **Timeline**: 2-3 weeks
- **Proof**: Early adopters, founder story, problem interviews

#### Growth
- **Primary**: April Dunford Positioning Canvas
- **Secondary**: Competitive positioning + Perceptual mapping
- **Why**: Compete on differentiation (what you do that others can't)
- **Goal**: Competitive clarity, technical buyer mindset
- **Timeline**: 4-6 weeks
- **Proof**: Feature matrix, speed/reliability comparison, developer adoption

#### Mature
- **Primary**: Category Design
- **Secondary**: Blue Ocean framework
- **Why**: Own the category mindshare, not just the product market
- **Goal**: Define or redefine the category
- **Timeline**: 6-8 weeks
- **Proof**: Industry analyst reports, thought leadership, ecosystem

---

### 2. B2B Application SaaS

**Examples**: Salesforce, HubSpot, Notion, Monday, Asana

#### Pre-Launch
- **Primary**: Lean Canvas + Value Proposition Canvas
- **Secondary**: JTBD
- **Why**: Understand customer pain/gain, validate use case
- **Goal**: Problem-solution fit, early user traction
- **Timeline**: 2-3 weeks
- **Proof**: Customer conversations, early sign-ups, problem interviews

#### Growth
- **Primary**: Geoffrey Moore Template
- **Secondary**: STP Framework (Segmentation, Targeting, Positioning)
- **Why**: Multi-stakeholder buying journey, different roles care about different things
- **Goal**: Buying motion clarity, ROI communication
- **Timeline**: 4-6 weeks
- **Proof**: Case studies with metrics, ROI calculator, customer testimonials

#### Mature
- **Primary**: Category Design + Blue Ocean
- **Secondary**: Value migration analysis
- **Why**: Defend market leadership, reframe category
- **Goal**: Thought leadership, competitive advantage
- **Timeline**: 6-8 weeks
- **Proof**: Research reports, analyst relationships, ecosystem plays

### 5. Government SaaS / Federal Product

**Examples**: eCourt, IACP, Case Management, Grants Management

#### Pre-Launch
- **Primary**: Lean Canvas + Government buying psychology (compliance-first)
- **Secondary**: Value Prop Canvas
- **Why**: Understand government-specific requirements, validate compliance fit
- **Goal**: Government problem validation, compliance pathway clarity
- **Timeline**: 3-4 weeks
- **Proof**: Government interviews, compliance framework alignment, pilot plan

#### Growth (Deployment)
- **Primary**: Geoffrey Moore Template (emphasize compliance, not speed)
- **Secondary**: Government-specific STP (federal vs. state vs. local)
- **Why**: Government has different buying criteria (security, compliance, stability)
- **Goal**: Government buying motion, compliance clarity, risk reduction
- **Timeline**: 4-6 weeks
- **Proof**: Compliance certifications, government case studies, FedRAMP/ATO status

#### Mature (Ecosystem)
- **Primary**: Category Design (government AI category)
- **Secondary**: Blue Ocean (reframe what government IT looks like)
- **Why**: Own government modernization narrative
- **Goal**: Trusted government technology partner positioning
- **Timeline**: 6-8 weeks
- **Proof**: Government customer base, thought leadership, policy influence

## Buyer Type Variations (Same Framework, Different Messaging)

Once you select the framework above, customize messaging by buyer:

### Application SaaS (Geoffrey Moore) - Different Messaging by Buyer

**Same positioning framework, different emphasis**:

```
Business Buyer (CFO, VP Ops):
- Focus: ROI, cost savings, implementation speed
- Value prop: "Reduce costs by 30%, implement in 8 weeks"
- Proof: Financial metrics, implementation timeline
- Fear: Disruption, team adoption, hidden costs

Technical Buyer (CTO, VP Engineering):
- Focus: Integration, architecture, security, scalability
- Value prop: "Integrates with existing stack, zero downtime"
- Proof: Technical specs, architecture diagrams, security certifications
- Fear: Vendor lock-in, technical debt, migration risk

User (Individual using the software):
- Focus: Ease of use, time savings, does their job better
- Value prop: "Save 2 hours/day, 10x easier than previous tool"
- Proof: User testimonials, feature demos, ROI per user
- Fear: Training time, change, loss of current workflow
```

Same Geoffrey Moore framework, totally different messaging.

---

### Enterprise AI Service (Geoffrey Moore) - Different Messaging by Buyer

**Same positioning framework, different emphasis**:

```
CTO (Execution risk):
- Focus: Implementation speed, disruption risk, team capacity
- Value prop: "Deploy in 30 days, no system replacement"
- Proof: Deployment timeline, case studies, pilot approach
- Fear: Project overruns, team burnout, production disruption

CFO (Cost):
- Focus: Total cost, ROI, cost per system
- Value prop: "$300K for 3 systems vs. $5M consulting"
- Proof: Cost breakdown, ROI calculator, year 1 savings
- Fear: Hidden costs, overruns, future vendor lock-in

CISO (Compliance):
- Focus: Governance, audit trails, compliance
- Value prop: "Compliance built-in, continuous audit ready"
- Proof: Governance model, audit trail documentation, certifications
- Fear: New security risks, compliance gaps, audit failures
```

Same Geoffrey Moore framework, totally different messaging.
