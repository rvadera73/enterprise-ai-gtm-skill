# Positioning Framework by Product Type & Stage
**Systematic, Repeatable, Framework-Driven Approach**

Based on research into Stripe, Adobe, Salesforce, and 50+ SaaS companies, here's a **structured framework** (Shipley-style: systematic, auditable, repeatable) customized by product type and maturity stage.

---

## Framework Overview: The 4-Phase Positioning Model

```
┌─────────────────────────────────────────────────────────────┐
│ PHASE 1: DISCOVERY                                          │
│ Frameworks: Jobs-to-Be-Done + Value Proposition Canvas     │
│ Output: Job Definition + Customer Profile + Pain Map       │
│ Duration: 2-4 weeks                                        │
└─────────────────────┬───────────────────────────────────────┘

                      ↓

┌─────────────────────────────────────────────────────────────┐
│ PHASE 2: POSITIONING                                        │
│ Frameworks: April Dunford Canvas OR Geoffrey Moore Template │
│ Output: Positioning Statement + Target Segment Definition  │
│ Duration: 1-2 weeks                                        │
└─────────────────────┬───────────────────────────────────────┘

                      ↓

┌─────────────────────────────────────────────────────────────┐
│ PHASE 3: VALIDATION                                         │
│ Frameworks: Perceptual Mapping + 5-Second Clarity Test     │
│ Output: Competitive Differentiation + Message Clarity      │
│ Duration: 1 week                                           │
└─────────────────────┬───────────────────────────────────────┘

                      ↓

┌─────────────────────────────────────────────────────────────┐
│ PHASE 4: MESSAGING & ARTIFACTS                             │
│ Frameworks: STP (Segmentation) + Brand Archetype           │
│ Output: Segment-Specific Messaging + Brand Guidelines      │
│ Duration: 2-3 weeks                                        │
└─────────────────────────────────────────────────────────────┘
```

## Part 1: DEVTOOLS & INFRASTRUCTURE SaaS

**Category Type**: Developer-first, API/CLI-driven, infrastructure layer  
**Examples**: Stripe, Vercel, Linear, Figma, GitHub, Fly.io, Supabase

**Time-to-Clarity**: 4-6 weeks (framework-driven, not guesswork)

### Phase 1: Discovery (Jobs to Be Done + Value Prop Canvas)

**Primary Job**: What is the specific technical problem the developer needs solved?

| Element | DevTools-Specific Focus | Example (Linear) |
|---------|---|---|
| **Core Job** (Functional) | Solve a specific engineering workflow problem | "Reduce issue triage time from 5+ hours to 30 minutes" |
| **Core Job** (Emotional) | Make engineering faster, not slower; feel productive | "Stay in flow; don't context-switch" |
| **Core Job** (Social) | Engineer identity/reputation | "Be known as the team that ships fast" |
| **Customer Segment** | Engineering role + company size + company stage | "Tech Lead at 10-200 person SaaS startup" |
| **Pain Points** | Specific workflow friction | "Jira is bloated; GitHub Issues limited; Asana overkill" |
| **Gain Expectation** | Quantified outcome | "Save 5+ hours/week per engineer" |
| **Alternative** (Critical!) | What would they use if you didn't exist? | "Stay on Jira; build custom tooling; spreadsheet + email" |

**Artifacts to Produce** (DevTools discovery phase):
- Job definition statement (1-2 sentences)
- Customer persona (role, company size, pain specificity)
- Pain quantification (hours/week wasted, cost impact)
- Alternative landscape (3-5 alternatives + why insufficient)
- Aha moment (what makes them realize they need this?)

### Phase 2: Positioning (April Dunford Canvas)

**Template for DevTools**:

```
FOR [Developer role] at [company size/stage],
WHO [specific pain point with current tools],
[PRODUCT] is [category we define]
THAT [specific outcome/speed/efficiency benefit].

UNLIKE [primary alternative]:
- [We're] X where they're Y
- [We] have X where they lack it
- [We] prioritize X; they prioritize Y

BECAUSE [credibility/proof]:
- Founded by engineers who [relevant experience]
- Chosen by [specific customers doing meaningful work]
- [Quantified proof: speed benchmark, adoption, etc.]
```

**Example (Linear)**:
```
FOR Tech Leads at 10-200 person SaaS startups,
WHO waste 5+ hours/week on slow, bloated issue tracking,
Linear is the only issue tracker that prioritizes developer speed and experience.

UNLIKE Jira (bloated, slow, expensive):
- We're fast; Jira adds complexity
- We're $80/month; Jira is $500/month
- We were built by engineers for developers; Jira by enterprise managers

UNLIKE GitHub Issues (too limited):
- We have advanced workflows; GitHub has basic
- We integrate with any tool; GitHub is GitHub-centric

BECAUSE:
- Founded by engineers from Stripe, Google, Facebook who ship fast
- Chosen by 5,000+ engineering teams
- 3x faster than Jira on standard workflows (benchmark)
```

### Phase 3: Validation (Perceptual Mapping)

**2D Perceptual Map for DevTools**:
- **X-Axis**: Speed of Workflow (Fast → Bloated)
- **Y-Axis**: Feature Completeness (Full-featured → Minimal)

**Positioning Logic**:
```
Jira: Bloated + Full-featured (far right, top)
GitHub Issues: Fast + Minimal (left, bottom)
Linear: Fast + Full-featured (right, bottom) ← "Best of both"
Asana: Bloated + Full-featured (right, top) ← Competitor, not threat
```

**5-Second Clarity Test**: Can a developer understand your differentiation in 5 seconds?
- ❌ Bad: "Collaborative issue tracking platform for teams"
- ✅ Good: "3x faster than Jira, built for developers"

### Phase 4: Messaging & Brand (By Developer Persona)

**Segment 1: Tech Lead (Decision-maker)**
- **Pain**: "My team hates Jira, but I'm stuck with it"
- **Message**: "Give your team back 5+ hours/week. They'll ship faster."
- **Proof**: "100+ Series B SaaS companies rely on Linear"
- **CTA**: "See how Linear speeds up triage"

**Segment 2: Individual Engineer**
- **Pain**: "Constantly context-switching between tools"
- **Message**: "Stay in flow. Linear keeps you in your IDE."
- **Proof**: "Engineers rate Linear 9.2/10 for speed"
- **CTA**: "Try Linear free (no credit card)"

**Segment 3: Enterprise Engineering Manager**
- **Pain**: "Tool sprawl is out of control"
- **Message**: "Standardize on a tool your team loves"
- **Proof**: "Stripe, Figma, Vercel use Linear"
- **CTA**: "Schedule a demo"

**Brand Archetype**: The Creator (builds things, values craftsmanship) + The Hero (overcomes obstacles, enables progress)
- **Voice**: Confident, technical, minimal fluff
- **Example**: "We move fast. Our tool should too."

**Artifacts to Produce** (DevTools messaging phase):
- 3 segment-specific positioning statements
- Proof hierarchy (proof point #1, #2, #3 per segment)
- Brand voice guide (2-3 tone examples + anti-patterns)
- Messaging by channel (LinkedIn, technical blog, docs, Twitter)

## Part 2: APPLICATION SaaS (Multi-User, Business Team-Facing)

**Category Type**: Finance, HR, Operations, Productivity  
**Examples**: Salesforce, ServiceTitan, Notion, Monday, Calendly

**Time-to-Clarity**: 4-6 weeks

### Phase 1: Discovery (Value Proposition Canvas + Job Variants)

**Complexity**: Application SaaS has multiple user types + jobs, so map all of them:

| User Type | Primary Job | Emotional Job | Pain Points |
|---|---|---|---|
| **Finance Manager** | Reduce month-end close time | Feel confident in data accuracy | Manual reconciliation, siloed data |
| **CFO** | Make faster financial decisions | Reduce audit risk | Outdated reporting, compliance friction |
| **AP/AR Clerk** | Process invoices quickly | Reduce errors | Manual data entry, approval bottlenecks |

**Critical for Application SaaS**: Map the **buying job** vs. **using job**
- **Buying job** (CFO): "Reduce close time, improve compliance, reduce manual work"
- **Using job** (AP Clerk): "Process invoices faster without errors"

**Artifacts to Produce**:
- Job map (all user types + buying vs. using jobs)
- Pain quantification per user type (CFO: "month-end close takes 5 days, costs $150K labor")
- ROI calculation (outcome value to business buyer)
- Integration needs (what systems must connect?)

### Phase 2: Positioning (Geoffrey Moore Template for Multi-User SaaS)

**For application SaaS**, use Geoffrey Moore because you're positioning against established competitors with clear category:

```
FOR [buying persona],
WHO [specific business pain with current approach],
[PRODUCT] is a [category]
THAT [business outcome].

UNLIKE [incumbent]:
- [OUTCOME difference]: We deliver X; they deliver Y
- [BUYER EXPERIENCE]: Buying/implementing with us is X; with them is Y
- [RISK PROFILE]: Adoption risk X; total cost Y

WE can [differentiation] BECAUSE [credibility]:
- [Process advantage]
- [Technology advantage]
- [Customer proof]
```

**Example (Salesforce vs. SAP in early 2000s)**:
```
FOR Sales/Marketing VPs running enterprises,
WHO are stuck with Siebel/SAP's expensive, inflexible CRM,
Salesforce is the only cloud CRM
THAT lets you customize without code and grow without licensing costs.

UNLIKE Siebel/SAP:
- Outcome: They take 2 years to implement; we take 2 months
- Buyer experience: They require enterprise IT; we work with Sales directly
- Risk: They lock you into perpetual licensing; we charge per-user, per-month

We can do this BECAUSE:
- Cloud-native architecture (they're on-premise)
- No-code customization (they require developers)
- Consumption-based pricing (they're license-seat)
```

### Phase 3: Validation (Buyer Willingness Mapping)

**For application SaaS, validate against buying criteria, not just product features**:

| Buying Criteria | Traditional (SAP) | Cloud SaaS (Salesforce) | Your Position |
|---|---|---|---|
| **Implementation time** | 12-24 months | 2-4 months | ← Claim advantage? |
| **Total cost of ownership** | $2M+ over 5 years | $500K over 5 years | ← Where do you compete? |
| **Customization** | Requires developers | Low-code/no-code | ← What's your capability? |
| **Data integration** | IT-managed | Pre-built connectors | ← Pre-built with what? |
| **ROI timeline** | 3+ years | 6-9 months | ← Quantify your ROI |

### Phase 4: Messaging & Brand (By Buying Persona)

**Segment 1: Finance Leader (CFO, Controller)**
- **Buying criteria**: Compliance, accuracy, audit readiness
- **Message**: "Close your books in 3 days, not 5. Automated reconciliation, zero errors."
- **Proof**: "100+ Fortune 500 companies rely on [product]"
- **CTA**: "See ROI calculator"

**Segment 2: Operations Manager (User)**
- **Buying criteria**: Ease of use, speed, reduces manual work
- **Message**: "Process invoices in 5 minutes, not 50 minutes."
- **Proof**: "95% of users prefer us to their legacy system"
- **CTA**: "Try free for 14 days"

**Brand Archetype**: The Sage (information + clarity) + The Mentor (guides you to success)
- **Voice**: Trustworthy, clear, detail-oriented
- **Example**: "One source of truth. For your whole business."

**Artifacts to Produce**:
- ROI calculator (showing financial outcome)
- Compliance checklist (specific to their regulatory requirements)
- Implementation timeline (proof you deliver fast)
- Case study per industry/size (not generic case study)

## Part 3: MARKETPLACE & PLATFORM SAAS

**Category Type**: Two-sided or multi-sided network  
**Examples**: Shopify, Twilio, Stripe (when used as platform), Zapier, HubSpot

**Time-to-Clarity**: 6-8 weeks (dual customer jobs make this complex)

### Phase 1: Discovery (Dual Jobs to Be Done)

**Complexity**: You serve **two customers with different jobs**:
- **Seller job**: "Build a business selling online" (Shopify)
- **Buyer job**: "Find products easily" (implicit; Shopify manages this)

### Phase 2: Positioning (Category Leadership)

**For platforms, use Blue Ocean thinking**: Can you reframe the category entirely?

**Example (Shopify 2010)**:
- **Old category**: "E-commerce software" (compete with OSCommerce, Magento)
- **New category**: "Commerce platform" (position as solution for online sellers, not tech implementation)
- **Differentiation**: "You don't need a developer; Shopify is the developer"

### Phase 3: Validation (Network Effect Proof)

For marketplaces, validate:
- Supply-side growth (sellers increasing)
- Demand-side growth (buyers coming)
- Retention (not just acquisition)

### Phase 4: Messaging (Dual Messaging by User Type)

**For sellers**: "Start your business in 5 minutes. No coding required."  
**For buyers**: "Discover millions of products from sellers you trust."

## Part 4: EARLY-STAGE vs. GROWTH-STAGE POSITIONING

### Pre-Launch (Stealth/MVP Stage)

**Frameworks to use**: Lean Canvas + JTBD interviews

**Positioning Rule**: Lead with the problem and your founder credibility, not the product

**Artifacts**:
- Clear job definition (the problem you're solving)
- Founder credibility (why you're qualified to solve this)
- Early traction (beta waiting list, letter of intent, pilot customer)
- Vision statement (5-year category you're creating)

**Example messaging**: "We're fixing [specific problem] for [specific customer]. Our team previously shipped [relevant experience]. Want to be an early user?"

---

### Growth-Stage (Product-Market Fit)

**Frameworks to use**: Full STP framework + perceptual mapping + outcome-based messaging

**Positioning Rule**: Aggressive competitive differentiation + ROI quantification

**Artifacts**:
- Segment-specific positioning (not one-size-fits-all)
- Competitive positioning matrix
- ROI calculator
- Technical case study (proof this actually works)
- Sales collateral (one-pagers per competitor)

---

### Mature-Stage (Market Leadership)

**Frameworks to use**: Category design + Blue Ocean + thought leadership

**Positioning Rule**: Own the category; shift customer perception about what matters

**Artifacts**:
- Industry report (market research showing your viewpoint)
- Conference speaking (establish authority)
- Ecosystem positioning (partners, integrations)
- Vision for next evolution of category

## Part 5: MARKETING ARTIFACTS BY POSITIONING FRAMEWORK

Once you've completed the positioning framework, here's **what artifacts to produce** for each phase:

### Discovery Phase Artifacts
- [ ] Job definition statement (1-2 sentences)
- [ ] Customer persona (detailed, not generic)
- [ ] Pain quantification (hours wasted, money lost, risk)
- [ ] Alternative landscape (3-5 alternatives + gaps)
- [ ] Aha moment description (what triggers need recognition)
- [ ] Value Proposition Canvas (filled, visual)

### Positioning Phase Artifacts
- [ ] Positioning statement (using chosen framework template)
- [ ] Target segment definition (not "everyone")
- [ ] Competitive differentiation (vs. top 3 alternatives)
- [ ] Credibility assets (team experience, customer proof, benchmarks)
- [ ] Proof hierarchy (proof point 1, 2, 3 by importance)

### Validation Phase Artifacts
- [ ] Perceptual map (showing your competitive position)
- [ ] 5-second clarity test results (buyer feedback)
- [ ] Messaging clarity score (how many buyers understand you in 5 sec)
- [ ] Competitive messaging matrix (comparison by claim type)
- [ ] Buyer willingness assessment (do they prefer you on key criteria?)

### Messaging & Brand Phase Artifacts
- [ ] Segment-specific positioning (one per audience)
- [ ] Brand archetype definition (2 primary archetypes)
- [ ] Brand voice guide (tone examples + anti-patterns)
- [ ] Messaging by channel (LinkedIn/blog/docs/Twitter variations)
- [ ] Sales collateral (one-pagers vs. competitors)
- [ ] Website messaging (homepage hierarchy)
- [ ] Email campaign framework (educational + CTAs)
- [ ] Social content themes (30-day calendar)

## Decision Framework: Which Framework to Use?

| Product Type | Use This Framework | Why |
|---|---|---|
| **DevTools/Infrastructure** | April Dunford Canvas | Technical audience; need competitive clarity |
| **B2B Application SaaS** | Geoffrey Moore Template | Multiple stakeholders; need buyer journey mapping |
| **B2C/Marketplace** | Jobs to Be Done + Category Design | Dual customer jobs; network effect matters |
| **Enterprise/High-touch** | Moore + STP | Long sales cycles; multiple personas; segmentation critical |
| **Early-stage (MVP)** | Lean Canvas + JTBD | Unknown market; validate job exists first |
| **High-growth** | STP + Perceptual Mapping | Scaling positioning; need segment-specific messaging |
| **Market Leadership** | Category Design + Blue Ocean | Established; reframe the category |

## Implementation Checklist

**Week 1-2: Select Framework & Run Phase 1 (Discovery)**
- [ ] Identify your product type (DevTools, Application, Marketplace, etc.)
- [ ] Select appropriate framework from matrix above
- [ ] Schedule discovery workshops (2 sessions)
- [ ] Conduct 10 customer interviews using JTBD methodology
- [ ] Complete Value Proposition Canvas

**Week 3-4: Phase 2 (Positioning)**
- [ ] Fill out positioning framework template (April Dunford or Moore)
- [ ] Define target segment (not everyone)
- [ ] Map competitive alternatives
- [ ] Identify 3-5 proof points

**Week 5: Phase 3 (Validation)**
- [ ] Create perceptual map of competitive landscape
- [ ] Run 5-second clarity test (20 target customers)
- [ ] Refine positioning based on feedback
- [ ] Document competitive differentiation

**Week 6+: Phase 4 (Messaging & Artifacts)**
- [ ] Define segment-specific messaging (2-3 segments minimum)
- [ ] Select brand archetype(s)
- [ ] Create brand voice guide
- [ ] Build all downstream artifacts (website, email, social, sales collateral)

## Success Criteria

How do you know the framework worked?

✅ **Positioning clarity**: Team can articulate positioning in one sentence  
✅ **Customer resonance**: 7+ of 10 customers say "yes, that's our problem"  
✅ **Competitive defensibility**: You own something competitors can't credibly claim  
✅ **Messaging alignment**: Every channel (website, email, social, sales) reinforces same positioning  
✅ **Conversion improvement**: Landing page conversion or sales conversion increases 20%+  
✅ **Customer retention**: Positioning attracts the right customers (high NPS, low churn)

This is the key insight: **Framework determines which artifacts to produce.**

- ✅ Framework-driven: "We're using April Dunford Canvas. Here's what we need: positioning statement, perceptual map, segment-specific messaging, proof hierarchy"

Once the framework is complete, **marketing automation** can generate all artifacts aligned with the framework outputs, ensuring consistency and strategic alignment.
